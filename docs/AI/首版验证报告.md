## 真实对局与训练结果

下表所有分数来自实际 Unity 物理环境。正常完成的对局均为 `Lost`；预算截断单独标注。

| 运行 | 种子 | 最终分数 / 截断状态 | 动作数 |
| --- | --- | --- | --- |
| 接口覆盖验证 | 42 | 331，正常终局 | 172 |
| 随机基线 | 1000001 / 1000002 | 340 / 272，正常终局 | 296 / 245 |
| CPU PPO 短训练 | 1 / 2 | 289 / 259，正常终局 | 260 / 385 |
| 从检查点继续搜索训练 | 1 | 249，正常终局 | 233 |
| 确定性最大概率评估 | 1000001 | 持续等待，512 步截断；当时分数为 0 | 512 |
| 采样策略分布评估 | 1000001 / 1000002 | 273 / 348，正常终局 | 200 / 203 |

训练与评估均使用 CPU，动作间隔 6 个固定步、奖励缩放 1000。搜索验证使用每次 2 次模拟、8 步试演，属于流程检查预算。两局 PPO 的采样与更新分别约 3.9、5.3 秒；一局搜索续训约 14.0 秒。这些时间不含 Player 首次启动，且受机器和场景影响，不能直接推算大规模训练成本。

策略分布采样是当前默认评估方式；`--greedy` 用于最大概率动作的确定性对照。PPO 训练的是随机策略，未经充分训练时改用最大概率动作可能形成持续等待。评估器保留截断记录，不将其冒充正常失败，也不从统计中隐去截断率。

以上样本不足以比较算法强度、证明学习进步或判断数值平衡。随机基线与采样评估虽使用同一组种子，搜索会额外使用模拟预算；不能只凭两局均值宣布改进。需要扩大训练规模，预先划分验证/测试种子，并同时比较得分、完成率、截断率和计算成本。

## 产物与复现

- 训练 Player：`.utmp/game-ai/player/GameAI.exe`。
- PPO 检查点：`.utmp/game-ai/runs/validation-train/latest.pt`。
- 搜索续训检查点：`.utmp/game-ai/runs/validation-search/latest.pt`。
- 每次运行目录内的 `manifest.json` 保存参数、游戏内容哈希、Unity 构建清单与 Python 源码哈希。
- 对局轨迹、指标和摘要分别位于各目录的 `episode-*.json`、`metrics.jsonl`、`summary.json`。
- `validation-evaluate` 保存确定性截断结果；`validation-policy-evaluate` 保存采样策略评估结果。

可直接继续训练现有流程验证模型，并写入新的实验目录：

```powershell
.utmp\game-ai\venv\Scripts\python.exe Tools/GameAI/run.py train --checkpoint .utmp/game-ai/runs/validation-search/latest.pt --episodes 100 --search 16 --rollout-steps 64 --output .utmp/game-ai/runs/next-training
```

局数和搜索预算只是起始参数，应根据实际吞吐量和评估曲线调整。正式成果应在独立评估后选定，再保存到 `Assets/AI/Models`；当前没有选定正式模型。更多命令见 [使用说明](使用说明.md)。

## 环境处理与未覆盖范围

首次克隆中的 xLua 动态库和模型原本是 Git LFS 指针，现已下载仓库记录的实际内容。AI 批处理构建加入 Excel 自动导入保护；用户的 `GameBalance.json` 与启动前备份逐字节一致。Unity 自动写入的包源、编辑器版本、后台设置与字体缓存已恢复，不作为 AI 修改交付。构建清单保留实际构建时的数据。

本次仅验证同一 Windows/Unity 环境中的重放一致性，不承诺跨平台 PhysX 一致。尚未完成所有装置组合、完整正常交互帧循环、可视化播放效果和长期训练的全面验证。任意物理时刻快照、实时 MCTS、循环记忆、通用隐藏状态推断及 Unity 内嵌推理仍不在首版实现范围内。
