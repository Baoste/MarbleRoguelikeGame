# MarbleRoguelikeGame 数值策划上手指引

## 0. 先记住三条

1. **运行时读 JSON，不直接读 Excel。** `GameBalance.xlsx` 是基础数值编辑源，导入后生成 `GameBalance.json`。
2. **内容数值不在基础 Excel。** 34 个属性、15 种装置和 12 种药物以 `GameContent.json` 为当前运行来源。
3. **区域数值在场景。** 得分区倍率、Rush 概率、赌博区和碰撞范围在 `TestScene` 的 `MarbleZone` 组件中。

开始调参前先退出 Play Mode。运行中的 `MarbleSimulation` 持有配置深拷贝，修改磁盘文件后必须重新进入 Play 才会生效。

## 1. 当前已同步的调优基线

`GameBalance.xlsx` 与 `GameBalance.json` 已同步：每回合 100 血，阶段目标为 `120 / 380 / 815 / 1410 / 2200 / 3145`。这些值是 2026-09-30 Balance Pipeline 的 Recommended V5 方案：首回合目标设为 120，以该点为锚将 V4 曲线的后续增量缩放至 90%，再按 5 分档取整。后续修改基础战役参数仍应以 Excel 为编辑源，保存后检查生成 JSON 的差异。

本轮真实物理采样、120,000 局经济模拟、假设和局限见 [Balance 总览](Balance/balance_overview.md) 与 [模拟方法](Balance/simulation_methodology.md)。

### 2.1 哪些字段看起来能调，但 Campaign 不使用

`MarbleTuning` 和 `CampaignTuning` 中有一批 `[NonSerialized]` 兼容字段，例如旧的 `BaseScore`、`LaunchSpeed`、`BaseRestitution`、`GamblingWinChance` 和 `GamblingWinMultiplier`。它们仅供旧的“无内容目录”模拟 API 使用，Campaign 场景不会从 Excel、JSON 或 Inspector 读取这些值。

同理，`TestScene` 中 `StartingBlood` 和 `BallsPerSecond` 只在非 Campaign 模式生成临时配置；当前 `EnableCampaign = true`，实际血量和发射间隔来自 `GameBalance.json`。

## 3. 安全调参流程

### 3.1 调基础战役参数

1. 退出 Play Mode。
2. 打开 `Assets/Config/GameBalance.xlsx`。
3. `Marble`、`Campaign` 只修改 `Value` 列；阶段在 `Stages` 中逐行修改。
4. 不使用公式、宏、外链或 Excel 错误值；需要计算时先在别处算完，再粘贴为值。
5. 保存并切回 Unity，等待自动导入；也可手动执行 `Marbles ECS → Import Game Balance Excel`。
6. 确认 Console 没有导入错误，并检查 `Assets/Resources/GameBalance.json` 的实际差异。
7. 重新进入 Play，完成至少一次发射、排空、阶段判定和商店循环。

导入器采用“先解析和校验、成功后发布”的方式。失败时旧 JSON 保留，所以看到场景还能运行不代表新数值已经生效。

### 3.2 调属性、装置和药物

1. 退出 Play Mode。
2. 编辑 `Assets/Resources/GameContent.json`。
3. 保证属性 ID、装置 ID、药物 ID 唯一，默认值位于 Min/Max 范围内。
4. 保存后重新进入 Play。
5. 用 `Marbles ECS → Validate Attribute and Content Runtime` 做运行验证。

日常不要通过保存“规范修订版”工作簿来期待内容 JSON 自动更新。内容工作簿只在显式执行 `Marbles ECS → Import Attribute and Content Excel` 时导入；它更适合批量同步已经由程序实现的数值，不适合单独定义新行为。

### 3.3 调区域和盘面

1. 在 `TestScene` 选中对应终点对象。
2. 修改 `MarbleZone` 的 `Multiplier`、`BaseRushChance`、`RushEnabled`、`FlatScore` 或 Collider。
3. 保持全场 `TargetId` 为正数且唯一。
4. 保存场景并重新进入 Play。

场景数值不会被 Excel 或 JSON 导入器覆盖，也不会出现在基础数值差异中。

## 4. 发射成本与球属性

### 4.1 当前实际公式

```text
投入量 Investment = MinInvestment + (MaxInvestment - MinInvestment) × Flow

单球基础血耗 = Investment × BLOOD_COST
单次发射总血耗 = 单球最终血耗 × BALL_SPAWN_COUNT
```

药物和属性效果按定义的 `SET → ADD/MUL → CLAMP` 规则参与计算。`BLOOD_COST` 是特殊的“先乘后加”，其他可乘属性通常是“先加后乘”。批量发射在扣血前检查全部球；任一球创建失败会整批回滚，不扣血。

### 4.2 Flow 现在是 Rush 爆发杆

内容模式会在属性效果结算前应用以下投入曲线：

```text
投入倍率 I = Investment / MinInvestment
基础价值 = BALL_BASE_VALUE × I ^ FlowValueExponent
半径 = BALL_RADIUS × I ^ (1/3)
质量 = BALL_MASS × I
```

当前 `FlowValueExponent = 1.15`。1 档适合用更多球积累 Rush 检定和槽值；5 档每单位血量约有 27% 的价值效率溢价，适合在 Rush 开启后快速消耗血量形成爆发。发射速度仍由 `BALL_LAUNCH_SPEED` 独立控制。

### 4.3 当前基础值

| 属性 | 默认值 | 说明 |
| --- | ---: | --- |
| BLOOD_COST | 1 | 最低档每球 1 血，最高档每球 5 血 |
| BALL_SPAWN_COUNT | 1 | 每次发射 1 球 |
| BALL_BASE_VALUE | 1 | 球的基础价值 |
| BALL_RADIUS | 0.5 | 实际世界半径为 `0.5 × 0.16 = 0.08` |
| BALL_MASS | 1 kg | 直接设置 Rigidbody 质量 |
| BALL_LAUNCH_SPEED | 1 m/s | 受最大速度约束 |
| BALL_MAX_SPEED | 12 unit/s | 出生和物理步均限速 |
| BALL_BOUNCE | 0 | 内容属性范围 0..2 |
| BALL_FRICTION | 0.25 | 静摩擦和动摩擦 |
| BALL_LIFETIME | 30 秒 | 从原始出生 Tick 计算 |
| FireIntervalSeconds | 0.3 秒 | Campaign 连发约 3.33 球/秒 |

## 5. 得分公式

内容模式下，一颗进入有效终点的球按以下顺序计算：

```text
基础价值 V0 = max(0, BALL_BASE_VALUE + 临时加值)

速度后价值 V1 = V0 × (1 + SCORE_BY_SPEED × clamp01(入区速度 / BALL_MAX_SPEED))

若结算前已处于 Rush：
V2 = V1 × 该球的 Rush 得分倍率
否则 V2 = V1

机器乘区 M = min(MACHINE_MULT 上限,
                  球的 MACHINE_MULT × 永久装置倍率 × 区域 Multiplier)

全局乘区 G = min(GLOBAL_MULT 上限,
                  max(GLOBAL_MULT, Rush 时的 RUSH_MULT) × 其他临时倍率)

普通区原始得分 = (V2 × M + FlatScore) × G

赌博区入池分 = 普通区原始得分
             × min(GAMBLE_POT_VALUE 上限,
                   BALL_GAMBLE_VALUE_MOD × GAMBLE_POT_VALUE)
```

重要边界：

- 当前 `MACHINE_MULT` 上限 100，`GLOBAL_MULT` 上限 100，赌博池倍率上限 10。
- 每球分数再受 `MaxPerMarbleScore = 1,000,000,000` 限制；每回合受 `MaxRoundScore = 9,000,000,000,000` 限制。
- 结算使用向下取整，但小数余量会在本回合同类分数中继续累计，不是每球都永久丢掉小数。
- 当前球先按结算前的 Rush 状态得分，再进行自己的 Rush 触发检定，所以它不能享受自己刚触发的 Rush。
- 赌博球入池时已经完成得分与 Rush 修正，开奖时只乘赌博结果，不再重新乘 Rush。

### 5.1 当前场景终点的名义收益

| 终点 | 区域倍率 | 普通无增益球的名义值 | Rush 检定 |
| --- | ---: | ---: | --- |
| 普通得分区 TargetId 5 | 1 | 1 分 | 关闭 |
| 普通得分区 TargetId 2 | 6 | 6 分 | 基础 12% |
| 赌博分区 TargetId 1 | 1 | 1 分入池 | 关闭 |

以上只比较数值，不包含区域面积、实际落点概率和装置路线。做平衡判断时必须把物理命中率一起测量。

## 6. Rush 规则

### 6.1 触发

Rush 开启的得分区会执行概率检定：

```text
普通球概率 = clamp01(区域 BaseRushChance + 球特性加成 + 装置/临时加成)
四叶草球概率 = clamp01(75% + 球特性加成 + 装置/临时加成)
```

同一球家族的四叶草检定只执行一次。除此之外，每次 Rush 开启的有效得分还会增加 `BALL_RUSH_GAIN`；槽值达到 `RushThreshold` 时强制触发一次并取余。

### 6.2 当前默认值

| 参数 | 当前值 |
| --- | ---: |
| BALL_RUSH_GAIN | 1 |
| RushThreshold | 8 |
| RUSH_DURATION 默认值 | 5 秒 |
| RUSH_DURATION 上限 | 8 秒 |
| RUSH_MULT | 2.5 |
| RUSH_DECAY | 1/秒 |

触发时使用 `max(当前剩余时间, 触发球的 RUSH_DURATION)`，再按上限夹紧。当前实现是刷新到较长剩余值，不是把每次持续时间相加。非 Rush 时，槽值也会按 `RUSH_DECAY` 衰减。

延长药剂会把触发球的 Rush 时长乘以 1.5，因此当前有效窗口为 7.5 秒；仍低于 8 秒上限，药剂保留了明确收益。

Rush 全局倍率与 `GLOBAL_MULT` 取较大值，不相乘。默认两者分别为 2.5 和 1，因此普通 Rush 为 ×2.5；如果后续把常驻 `GLOBAL_MULT` 调到高于 Rush，Rush 不会额外再乘一层。

## 7. 赌博池

所有赌博分区共用本回合一个待定分池。球进入赌博区时只增加 `PendingScore`，场内球排空后统一开奖一次。

当前四档权重为 30% / 30% / 25% / 15%：

| 结果 | 倍率 | 权重 |
| --- | ---: | ---: |
| 全损 | ×0 | 30% |
| 返还 | ×1 | 30% |
| 双倍 | ×2 | 25% |
| 四倍 | ×4 | 15% |

当前理论期望倍率为：

```text
0×30% + 1×30% + 2×25% + 4×15% = 1.40
```

代码按四项权重总和进行比例抽取，所以运行时权重经过效果修改后不必恰好等于 1，但总和必须大于 0。内容工作簿导入时，基础默认概率要求合计为 1。

按当前场景，一个普通球进高倍普通区名义得 6 分，进赌博区名义入池 1 分、期望结算 1.40 分。赌博区是否有吸引力主要取决于物理命中率、路线、池倍率和构筑，不应只因“期望倍率大于 1”就判断奖励足够。

## 8. 阶段与经济公式

### 8.1 提现

提现解锁条件：

```text
累计总分 + 本回合已确认即时分 >= 当前阶段目标
并且剩余血量 > 0
```

赌博待定分不参与解锁。提现金币为：

```text
floor(剩余血量
    × BLOOD_DIVIDEND_RATE
    × 当前阶段 CashoutRate
    × COIN_GAIN_RATE)
```

提现后血量直接归零，进入排空；已有球继续运动，赌博池仍会正常开奖。

### 8.2 阶段奖励与越级

结算后，总分每跨过一个阶段都会取得该阶段 `RewardCoins`。从本回合起点之后额外跨过的阶段，还会追加对应阶段的 `SkipRewardCoins`。

内容模式还会计算本回合新产生的超额分金币：

```text
超额分 = max(0, 新总分 - max(结算前总分, 当前阶段目标))
超额金币 = floor(超额分 × 0.01 × SCORE_OVERKILL_RATE)
```

阶段奖励与超额金币合计后再乘 `COIN_GAIN_RATE`。出售退款不受 `COIN_GAIN_RATE` 放大。

### 8.3 商店

```text
商品价 = max(1, floor(基础价格 × SHOP_PRICE_MOD))
刷新价 = max(1, floor(ShopRefreshCost × SHOP_PRICE_MOD))
出售退款 = floor(购入时记录的价格 × SellRatio)
```

每轮商店从完整目录分别等概率抽取 3 个不同装置、1 个药物，不再保底 Rush 类型。每回合进入商店或付费刷新时重新抽取，购买不会重抽其他货位；跨回合允许再次遇到同一种商品。商店使用独立随机序列，每次新开局重新生成种子，不受固定计分种子影响。

`Campaign.ShopOfferCount = 4` 控制总货位数，`Campaign.ShopDrugOfferCount = 1` 控制药物货位数，其余为装置。旧 Excel 未填写新字段时默认 1；某类目录不足时只展示该类现有的不同商品，不用另一类补位。

## 10. 推荐的平衡迭代顺序

一次只改变一个主要层级，避免同时移动目标、基础得分、区域倍率和经济后无法归因。

### 第一步：锁定基线

- 确认 Excel/JSON 仍然同步。
- 记录提交号、JSON 哈希、场景版本和随机种子。
- 记录 `FlowValueExponent` 和当前 Rush 药物行为字段。

### 第二步：标定无构筑单球产出

- 分别测量 x1 区、x6 区、赌博区和落空的真实命中率。
- 统计每单位血量的即时分、待定分和最终分。
- 分开记录“物理命中率”和“命中后的数值倍率”。

### 第三步：标定阶段压力

- 先调阶段 1，使新玩家能理解布置、发射、排空和商店。
- 再观察阶段 2 的构筑要求，不要只按目标倍率推算。
- 用通关率、剩余血量和回合耗时决定目标，而不是只看平均分。

### 第四步：标定风险系统

- 检查赌博区的实际单位血量期望、方差和“失败后是否仍能继续”的体验。
- 检查 Rush 覆盖率，而不只看触发概率；覆盖率同时受持续时间、衰减和进球间隔影响。
- 检查高乘区组合是否过早碰到 100×/100× 上限。

### 第五步：标定经济

- 以每过一阶段可负担的商品数量为核心，而不是孤立看价格。
- 统计刷新后无可买项、库存已满、重复商品和出售亏损对节奏的影响。
- 分开追踪提现、阶段奖励、超额奖励、银行收入和出售退款。

### 第六步：压力测试

- 高球数、复制、分裂和无限增值组合。
- 极端速度、半径、质量、弹性和生命周期。
- 得分上限、金币上限、库存上限和排空超时。
- 赌博权重总和接近 0、概率边界 0/1、空库存和余额刚好等于价格。

## 11. 建议采集的最小数据

项目当前没有随仓库提供可直接使用的数值遥测。至少为每局记录：

| 类别 | 字段建议 |
| --- | --- |
| 版本 | RunId、GitCommit、ConfigHash、RandomSeed |
| 阶段 | Stage、Target、Clear/Lost/Won、SkippedStages |
| 发射 | Shots、Flow 分布、BloodSpent、RoundDuration、MaxActiveMarbles |
| 得分 | ImmediateScore、PendingStake、GambleMultiplier、GamblePayout、RoundScore、TotalScore |
| Rush | Triggers、RushTime、RushScoreShare、MeterTriggers |
| 经济 | CashoutCoins、StageReward、OverkillCoins、BankCoins、CoinsSpent、RefreshCount、SellRefund |
| 构筑 | OwnedDevices、PlacedDevices、DrugUses、关键组合 |
| 物理 | 各终点命中数、Drain/Timeout/OutOfBounds 数量 |

建议先用固定配置跑一组可重复的基线，再改变单一参数。物理不保证跨平台确定性，因此同一随机种子也要保留多次运行样本。

## 12. 校验规则速查

- `Stages.TargetScore` 必须严格递增，且不超过 `MaxTotalScore`。
- 阶段、装置、药物 ID 必须唯一；属性必须完整覆盖 `GameAttribute` 枚举。
- 属性默认值必须位于 Min/Max 之间；所有数值必须有限，不能是 NaN 或 Infinity。
- 初始装置数量和药物数量不能超过各自容量；传送门每份占两个装置实体。
- 基础内容导入时，四个赌博概率合计必须为 1。
- `ShopOfferCount` 为 1..12；出售比例为 0..1。
- `MaxPerMarbleScore <= MaxRoundScore <= 9×10^15`。
- Excel 中超过 15 位的整数应以文本保存，避免精度丢失。
- 修改行为描述不等于修改行为。装置/药物特殊逻辑在 C# 中，改文案后内容导入器会要求程序审查。

## 13. 常见问题

### 修改 Excel 后为什么没变化？

先看 Unity Console 是否导入失败，再看 `GameBalance.json` 是否真的变化。即使 JSON 已变化，运行中的会话也不会热更新，必须退出并重新进入 Play。

### 为什么改了 `GameBalance.json`，之后又被改回去了？

它是 `GameBalance.xlsx` 的生成结果。保存 Excel 或手动导入都会覆盖它。长期修改应回到 Excel。

### 为什么改 `GameBalance.xlsx` 不能改球价值、速度或 Rush？

这些字段已经迁移到 `GameContent.json`。基础 Excel 只保留 Marble、Campaign、Stages 和说明页。

### 为什么高投入档的球更大、更重、更值钱？

当前内容模式把 Flow 作为爆发杆：价值按投入量的 1.15 次方增长，半径按立方根增长，质量线性增长。对应指数由 `GameContent.json` 的 `FlowValueExponent` 控制。

### 为什么待定分很多却不能提现？

提现只认累计总分和本回合已确认即时分。赌博池可能全损，所以在开奖前不计入提现资格。

### 为什么旧文档写 50% 赢 ×3，游戏却出现 ×0/×1/×2/×4？

当前 `GameContent.json` 和 `CampaignSettlementSystem` 使用四档权重，默认 `30% / 30% / 25% / 15%`。旧说明属于历史规则。

### 仓库里为什么找不到历史验证记录提到的测试与试玩包？

当前检出没有 `Assets/Tests`、`Assets/Verification~` 和 `Builds/BloodMarble`。`Builds/` 本身也被忽略。本轮已新增 `Tools/Balance/rush_balance_model.py`，但 Unity Play Mode 验证和试玩包仍需重新建立。
