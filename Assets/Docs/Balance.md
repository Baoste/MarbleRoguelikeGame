# 首版数值与 Excel 调参

运行数值的入口是 [`Config/GameBalance.xlsx`](../Config/GameBalance.xlsx)。原始 [`PachinkoECSDesign_3D.xlsx`](../PachinkoECSDesign_3D.xlsx) 保留为架构规格，最新玩法选择以 [`GameplayFlow.md`](GameplayFlow.md) 为准；本文件补全首版尚未定案的数值和边界。

## 策划操作

1. 用 Excel 或兼容的表格软件打开 `Assets/Config/GameBalance.xlsx`。
2. `Marble`、`Campaign`、`Board` 表只改 `Value` 列，旁边有中文字段说明；其他表每行一条配置，表头批注说明各字段。修改阶段目标只改 `Stages.TargetScore`。
3. 保存工作簿，回到 Unity 等待资源刷新。也可执行菜单 **Marbles ECS → Import Game Balance Excel**。
4. Console 提示导入成功后，退出 Play 再进入，应用新数值。HUD 的“重新开始整局”只重置当前配置下的资源，不重新加载 JSON。已打包的试玩程序须重新构建后启动。运行中的会话使用配置深拷贝，改表不会改变正在结算的球或交易。

导入生成 [`Resources/GameBalance.json`](../Resources/GameBalance.json)。构建只加载这个 JSON，不携带任何 Excel 运行库。Unity 编辑器使用 .NET 自带的 ZIP 和 XML API，无需安装第三方插件；制作这份工作簿的维护脚本使用的 `openpyxl` 不属于 Unity 依赖。

字段名、表名、必需列不能删除或改名。字段重排、配置行增减按各表数量约束处理；`Stages` 的行序就是关卡顺序，目标必须严格递增。概率用 `0..1`，时间用秒，空间长度用米；布尔值支持 Excel 的 `TRUE/FALSE` 和 `1/0`。不支持公式，计算结果须粘贴为值。超过 15 位的整数按文本保存，避免 Excel 自动舍入。

NaN、无穷、Excel 错误单元格、重复 ID、缺少字段、非法整数、未知工作表、越界盘面和非法跨表组合都会拒绝导入。**校验失败时，旧 JSON 不会被覆盖。** 全部解析和校验完成后才写临时文件，并在同目录备份旧 JSON 后发布；遇到发布错误尝试恢复旧文件。若磁盘或权限错误连恢复也失败，Console 会给出保留下来的 `.bak` 路径。只读工作簿可导入；如果 Excel 正在保存时读取失败，保存完成后再次执行菜单即可。

## 初版规则与数值

这些数值用于第一轮可玩性验证，并非已经经过玩家样本调优。基础分与耗血档位独立：提高抽血档位会改变耗血、半径和质量，不自动提升基础分。高档位的价值来自不同的碰撞路径，需要后续体验数据验证。

| 项目 | 默认值与含义 |
|---|---|
| 每回合血量 | 100；每颗投入 1～5，实际耗血乘数 1 |
| 血珠 | 基础分 10；半径 0.12～0.22 m；每血单位质量 0.1 kg |
| 发射 | 间隔 0.3 秒、速度 5 m/s，可横移发射位置 |
| 基础碰撞恢复系数 | 0.45；药物修改后限制在 0～1 |
| Rush | 基础概率 6%，一次增加 5 秒，剩余时长最多 20 秒；得分固定 x2 |
| 初始资源 | 30 金币；2 颗倍分钉、1 颗 Rush 钉；两种药物各 1 瓶 |
| 商店 | 4 个随机货架，可出现重复商品；每格买 1 件；刷新花费 5 金币 |
| 出售 | 按装置购入价格的 50% 向下取整；不提供升级或合成 |
| 容量 | 装置总数 20，药物库存总件数 30，同时生效药物最多 16 次 |
| 统一开奖 | 本回合所有赌博区共用一个待定分数池；排空后开奖一次，50% 胜率，赢得待定分数 x3 |
| 提现 | 仅当“已结算累计总分 + 本回合即时分”达到当前累计目标时允许；待定赌博分不计入门槛 |

提现金币为 `floor(剩余血量 × Campaign.CashoutCoinsPerBlood × 当前阶段.CashoutRate)`。基础兑换系数为 `0.5`，例如第一阶段剩余 40 血可提现 20 金币。提现后禁止发射，场内血珠继续运动直到排空，再开奖和判断通关。

| 阶段 | 累计目标 | 通关金币 | 越过该阶段的额外金币 | 提现阶段系数 |
|---|---:|---:|---:|---:|
| 1 | 350 | 30 | 15 | 1.0 |
| 2 | 1,000 | 40 | 20 | 1.1 |
| 3 | 2,200 | 50 | 25 | 1.2 |
| 4 | 4,200 | 60 | 30 | 1.3 |
| 5 | 7,500 | 75 | 40 | 1.4 |
| 6 | 12,000 | 100 | 50 | 1.5 |

达到目标采用 `>=`。一次超过多个后续目标时直接跳过已满足的阶段，获得各阶段通关奖励，并对额外跨过的阶段加发对应越级奖励。全部六阶段达成后胜利；未达到当前目标则失败。总分、金币、已拥有装置和药物库存跨回合保留，重开整局全部重置；回合临时效果会清空。

### 两种装置

| Id | 名称 | 价格 | 碰撞 Enter 效果 | 初始数量 |
|---|---|---:|---|---:|
| 1 | 倍分钉 | 25 | 当前血珠永久得分倍率 x2 | 2 |
| 2 | Rush 钉 | 20 | 当前血珠进入得分区时 Rush 概率增加 8 个百分点 | 1 |

装置默认半径 0.18 m。同一颗血珠对同一枚钉子只生效一次，离开后再次撞上也不重复触发；命中不同钉子可以继续叠加。倍率乘法叠加，血珠永久倍率上限 1000；Rush 概率加法叠加，最终限制在 `0..1`。Rush 钉不会在碰撞时直接开启 Rush，仍须血珠进入启用 Rush 的终点区。

### 两种药物

| Id | 名称 | 价格 | 恢复系数乘数 | 持续时间 |
|---|---|---:|---:|---:|
| 1 | 弹性剂 | 10 | x1.5 | 12 秒 |
| 2 | 缓弹剂 | 8 | x0.65 | 12 秒 |

药物只改变血珠的碰撞恢复系数。每次用药独立计时，在生效时段内新发射的血珠读取所有有效药物乘数的乘积；已有场内血珠保留发射时的恢复系数，不在药效到期时突变。相同或不同药物都可叠加；先求完整乘积、最后限制恢复系数到 `0..1`，因此用药先后顺序不改变结果。例：两次弹性剂为 `min(1, 0.45 × 1.5 × 1.5) = 1`；弹性剂与缓弹剂为 `0.43875`。

药物计时使用模拟时间；暂停时不流逝。药物不直接影响基础分、倍率、Rush 概率、质量或血量。

### 终点、Rush 与取整

终点分数为 `floor(血珠基础分 × 发射器倍率 × 血珠装置倍率 × 区域倍率 × 当前 Rush 倍率)`，再受单珠和回合上限约束。普通区立即加到回合分；赌博区将同样算出的分数加入待定池，开奖时不再重复乘 Rush。

当前球先按结算前的 Rush 状态计算分数，再进行本次 Rush 抽签。新触发的 Rush 不追溯放大当前球；活动期间再次触发只追加剩余时间，得分始终 x2。落空区无分，不触发 Rush。金币与分数均向下取整；单珠上限 `10^9`，单回合上限 `9×10^12`，累计分数上限 `9×10^15`。

默认盘面底部从左至右为：落空、普通 x1、赌博、普通 x1.5、落空。赌博区名称中的 x3 表示统一开奖的获胜倍率；它本身的 `ScoreMultiplier` 为 1。

## 工作表与接口

| 工作表 | 运行时类型 | 主要字段 |
|---|---|---|
| Marble | `MarbleTuning` | 血量、投入、半径、质量、基础分、发射、恢复系数、Rush、回收和分数上限 |
| Campaign | `CampaignTuning` | 初始金币、提现基础系数、刷新价格、货架数、出售比例、容量、开奖参数、总分上限 |
| Stages | `StageDefinition[]` | `Id / TargetScore / RewardCoins / SkipRewardCoins / CashoutRate` |
| Devices | `DeviceDefinition[]` | `Id / Name / Price / ScoreMultiplier / RushChanceAdd / Radius / StartingCount` |
| Drugs | `DrugDefinition[]` | `Id / Name / Price / RestitutionMultiplier / DurationSeconds / StartingCount` |
| Board | `BoardTuning` | 盘面尺寸、倾角、边墙、放置范围、固定钉布局、发射位置和固定步长 |
| Zones | `ZoneDefinition[]` | `Id / Name / Kind / ScoreMultiplier / RushEnabled / Priority / CenterX / CenterZ / Width / Depth` |

`Kind` 使用 `0=普通得分`、`1=统一赌博池`、`2=落空`。区域 ID 限定为 `1..99999`，避免与运行时装置碰撞编号空间冲突。必须至少存在一种普通区、赌博区和落空区。首版严格保留两种装置，分别为固定 x2 和仅提高 Rush 概率的钉子；药物表保留两条恢复系数定义。

所有类型位于 `MarblesECS.Rules` 程序集，使用普通 `[Serializable]` 字段，不依赖 Unity。`GameBalance.Default()` 创建初版默认值，`Validate()` 校验，`Copy()` 深拷贝全部定义行。`GameBalanceLoader.Load(TextAsset source = null)` 优先读取指定 JSON，否则读取 `Resources/GameBalance`；资源缺失时提示并使用默认值，非法 JSON 不会静默采用其他数值。战役每回合补血使用 `Marble.BloodCapacity`，目标使用 `Stages.TargetScore`；`Marble.InitialBlood` 和 `Marble.TargetScore` 仅供旧独立模拟使用。

### 三维盘面约定

Unity 实现采用局部 **XZ 为底板、+Y 为法线**；盘面根对象旋转为 `Quaternion.Euler(-TiltDegrees, 0, 0)`，所以正 Z 高、血珠向负 Z 运动。这与原设计表的 XY 盘面轴约定不同，统一在构建和表现层做映射；血珠仍是三维刚体，不冻结轴。

默认底板 `10×16 m`，厚 `0.35 m`，倾角 `22°`；发射位置 `(0, 0.35, 6.5)`；布置范围 X 为 `[-4,4]`、Z 为 `[-4.5,5]`。布置时检查装置完整半径、固定钉、其他装置和间距，越界或重叠不提交。默认自由放置；按住 Shift 点击时，使用 `GridSize`（默认 `0.5 m`）对齐网格，可设为 0 关闭这种辅助吸附。

固定普通钉为 5 排，偶数排 7 颗、奇数排 6 颗。排号和列号从 0 开始：

```text
count = FixedPinColumns - row % 2
x = (column - (count - 1) / 2) × FixedPinSpacingX
z = FixedPinStartZ - row × FixedPinSpacingZ
```

默认 X 间距 `1.15 m`、Z 间距 `1.65 m`、第一排 Z 为 `3.7 m`，普通钉半径 `0.13 m`。此公式同时用于物理生成和布置校验。

## 验证与后续调参

执行 `python Tools/Balance/verify_importer.py` 可在不启动 Unity 的情况下编译实际 Rules、Excel 解析器和导入事务代码，验证工作簿、默认值与 JSON 一致，验证共享字符串/内联字符串、深拷贝、独立修改目标，以及非法输入不覆盖旧资产。需要本机 .NET 9 SDK；无网络包还原、无 Python 第三方依赖。该验证替换了 Unity 资源刷新和 JSON 的适配器，不能替代实际 Unity 编译或物理测试。

`Tools/Balance/create_workbook.py` 仅供程序维护时从已审阅的 JSON 重建工作簿，需要 `openpyxl`。默认拒绝覆盖；`--overwrite` 会覆盖工作簿，不应对包含未导入策划改动的表使用。

建议先记录首关成功率、每 100 血平均得分、每颗血珠命中装置次数、Rush 覆盖时长和每阶段提现金币，再调 `Stages.TargetScore`、装置价格与概率。物理路径相关的半径、倾角、发射速度和恢复系数须结合实际盘面测试；只用分数公式无法预测最终命中分布。
