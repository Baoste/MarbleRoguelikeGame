# 属性、装置与药物实现

实现依据：规范修订工作簿的 `00_ATTRIBUTE_DICTIONARY (2)` 和 `设计总表`。
不导入旧 `效果参数`，因为设计 ID、内容与参数已经不一致；不实现道具。
赌博按本次确认改为全损 ×0、返还 ×1、双倍 ×2、四倍 ×4，各 25%。

## 配置与使用

- `Resources/GameContent.json` 配置属性和药物；装置以 `Resources/Devices/*.mres` 为唯一运行时来源。半径、质量、基础分、弹性、发射速度、寿命、Rush 和赌博等属性不再叠乘旧数值；完整对应关系见 `Balance.md`。
- `Resources/GameBalance.json` 只保留血量、抽血档位、发射间隔、容量、阶段及战役参数，不再保存重复属性、`Devices`、`Drugs`、`Board`、`Zones`。
- 盘面由场景手工搭建，区域在 `MarbleZone` 和 Trigger Collider 中配置；网格和间距在 `MarbleGameController.GridSize/PlacementClearance` 配置，固定钉避让检测 `PlacementObstacleRoots` 下实际启用的非 Trigger Collider。`TestScene` 已绑定 `PhysicsRoot/MarblePins`，完整迁移说明见 `Balance.md`。
- `Resources/GameContent.json` 保存 34 个属性定义、12 种药物和内容规则；其中 `Devices` 是从当前 `.mres` 完整生成的离线平衡工具快照。新增、修改、删除包及导入 JSON 时自动同步，旧条目不会合并回来；手动同步与离线命令见 `Balance.md`。
- `GameBalanceLoader` 加载基础配置、属性药物配置和 MRes 装置目录，装置／药物列表直接引用会话内容目录；运行会话深拷贝后仍共享该会话的一份目录，避免两份数据不同步。
- 直接修改内容 JSON，重新进入 Play 后生效。保存规范工作簿不再自动覆盖内容 JSON；显式执行 `Marbles ECS/Import Attribute and Content Excel` 才会把表中数值导入。
- 数值属性列可直接导入。药物总表中的自然语言效果不是脚本，需同步审阅配方；装置由 `.mres` 中的 Lua 和参数定义，Excel 导入不会覆盖它们。
- `Editor/Balance/build_content.py` 只补充缺少的属性和药物，保留其已有数值；装置列表每次重新读取当前 MRes，不沿用旧 JSON。日常属性和药物修改内容 JSON，装置修改制作源并重新打包。
- 重复原 ID（如 D009、M006）保留在 `SourceId`，运行 ID 按已注册内容名称分配：装置 100～114、表内药物 100～109，旧药物 1、2。
- 全部装置位于 `Resources/Devices/*.mres`，当前为 35 种（34 个 MResPacker 成品和 Multi Ding），外观、碰撞体和 Lua 行为随包加载，不再绑定装置 prefab。详见 [MRes 装置目录](../Resources/Devices/README.md)。放置时按 R 旋转 45°。
- 传送门按一对购买，两门分别放置并共享配对 ID；两门都放置后才可传送。
- 已有场景没有程序 HUD 时，控制器会提供可展开的药物库存面板。

装置基础购买价 `metadata.purchasePrice` 当前均为 5，单件出售价格读取 `metadata.value`；普通/稀有/史诗/传奇由 `metadata.rarity` 表示，耐久读取 `metadata.durability`（默认 20，-1 无限）。药物价格与初始数量仍在内容 JSON 中配置，初始赠送均以当前配置为准。

`Multi Ding` 的定义 ID 为 113，行为通过 Lua 实现；当前包的 `StartingCount` 为 1，没有额外的 C# 开局赠送规则。Rush Ding 已移出当前装置目录。旧药物保留 ID 1、2，在 `GameContent.json` 中配置。`SourceId` 继续记录原始来源编号。

`Multi Ding` 每球每装置提供 1.85 倍率一次，只累加其中的 0.85；全部装置到得分区以 `1 + Σ(倍率 - 1)` 统一计算，基础 ×1 只算一次。猪猪存钱罐每次有效撞击按钱包提供 `1 + 0.1 × floor(金币/10)`，两次 1.2 得到 1.4。旧 `Rush Ding` 的概率字段仅兼容，不参与累积 RUSH。旧药物 `Up Restitution` / `Down Restitution` 在 12 秒窗口内给新球的 `BALL_BOUNCE` 分别乘 1.5 / 0.65，独立计时叠加；与新药物共用属性运算顺序及字典上限 2。两种旧药物合计同时生效剂量仍受 `MaxActiveBounceDrugs` 限制，面板显示库存和剩余药效时间。

## 属性规则

所有属性使用字典上下限；count 属性在最终夹紧后向下取整。
SET 先确定基值，优先级高者胜，同优先级取效果列表中最后一项；之后按 Stack_Rule 执行 ADD、MUL，最后统一夹紧。
BLOOD_COST 是先乘后加；其他可乘属性为先加后乘；分裂数量和穿透次数拒绝 MUL。
效果支持来源 ID、覆盖刷新、到期 tick。全局永久效果跨回合保留，临时全局效果在回合复位时清除。

公开入口：`ApplyAttribute`、`ApplyGlobalAttribute`、`ApplyDeviceAttribute`、`GetMarbleAttribute`、`GetGlobalAttribute`。同来源和属性替换旧效果；这些入口为后续构筑系统提供能力，本次不生成道具。

| 属性 | 生效位置 |
|---|---|
| BLOOD_COST | 出生前计算，每颗球收费；批量生成全部成功才一起扣血 |
| BLOOD_DIVIDEND_RATE | 主动提现的每单位剩余血量兑换金币数；再应用阶段倍率和金币获取倍率 |
| BALL_SPAWN_COUNT | 一次发射生成一排互不重叠的球；不足容量／余额／空间则整批回滚 |
| BALL_BASE_VALUE | 出生、增值装置、银行和最终计分 |
| BALL_GAMBLE_VALUE_MOD | 与 GAMBLE_POT_VALUE 合并为一次赌池价值乘区 |
| BALL_RUSH_GAIN | 旧兼容属性；当前球贡献从 2 开始，每次有效装置作用 +5，通过 RushContribution API 累积 |
| BALL_RADIUS | 独立球体半径，乘 0.16 换算为世界单位；不随抽血档位变化 |
| BALL_MASS | 直接设置实际刚体质量，不再乘抽血量 |
| BALL_BOUNCE | 独立物理材质；静态／运动学障碍碰撞按球属性校正反弹，支持 0～2 |
| BALL_FRICTION | 独立材质的静摩擦和动摩擦 |
| BALL_GRAVITY_MOD | 每个 PhysX 子步按该球倍率施加重力 |
| BALL_LAUNCH_SPEED | 直接设置发射速度（m/s），生成后不持续加速 |
| BALL_MAX_SPEED | 出生、装置输出、每个物理子步结束限制速度 |
| BALL_MAGNET_RESPONSE | 磁性球受到装置磁力的倍率；0 免疫 |
| BALL_LIFETIME | 从原始出生 tick 计算清除时刻；子球继承出生时间和寿命期限 |
| BALL_SPLIT_COUNT | 普通圆钉接触时分裂，分裂子球不再自动触发同一个出生分裂效果 |
| BALL_CLONE_VALUE_RETENTION | 分裂子球价值比例；分流器明确使用 0.5，复制药物使用完整复制 |
| BALL_PIERCE_COUNT | 穿过普通圆钉的有限次数，与药物的穿钉概率分开计数 |
| MACHINE_MULT | 单球机器乘区，与既有装置／区域倍率合并后按字典 MaxValue 封顶，当前 100 |
| GLOBAL_MULT | 结算时读取；RUSH 不再自动乘全局倍率，而是临时价值 +5 |
| SCORE_BY_SPEED | 入区速度 / 最大速度得到 0～1 权重，对球价值加成 |
| SCORE_OVERKILL_RATE | 本轮新获得的超额分数 × 0.01 金币/分 × 此倍率；不重复兑换旧累计分 |
| RUSH_DURATION | 旧兼容属性；当前满 100 条值后固定 10 秒，再加触发球的 RushDurationBonus |
| RUSH_MULT | 旧兼容属性；不再自动乘入 RUSH 得分 |
| RUSH_DECAY | 旧兼容属性；当前条值不衰减，RUSH 每模拟秒倒计时 1 秒 |
| GAMBLE_LOSS_CHANCE | ×0 的概率权重 |
| GAMBLE_RETURN_CHANCE | ×1 的概率权重 |
| GAMBLE_WIN_CHANCE | ×2 的概率权重 |
| GAMBLE_QUADRUPLE_CHANCE | ×4 的概率权重 |
| GAMBLE_POT_VALUE | 与单球赌博修正合并，按字典 MaxValue 封顶，当前 10 |
| DEVICE_TRIGGER_RATE | 机关有效冷却除以触发率，0 禁止触发 |
| DEVICE_COOLDOWN | 装置基础冷却的秒数修正；最低有效间隔为一个玩法 tick |
| SHOP_PRICE_MOD | 商品和刷新价格，最低 1 金币；出售仍按原购买价格计算 |
| COIN_GAIN_RATE | 银行、提现、阶段／超额奖励各计算一次；出售退款不放大 |

默认概率合计必须为 1；运行时概率修正后按四项比例归一化，合计不得为 0。旧三档工作簿暂时兼容迁移为本次确认的四档各 25%；加入四倍属性后按工作簿直接导入。

空间口径：总表 cm 换算为 0.01 世界单位。BALL_RADIUS 使用 1 属性单位 = 0.16 世界单位，默认 0.5 对应 0.08 世界半径。尺寸、质量、基础价值和发射速度都直接使用内容属性；不再乘旧发射配置，也不随抽血档位隐式改变大小或质量。发射速度采用 m/s；药物和装置仍能通过属性效果修改这些数值。

每次用药消耗一瓶，窗口只决定哪些新发射球获得效果；窗口结束后，已生成球的属性仍保留。名称重复的旧 ID 不再串药。

复制／分裂继承家族、触发记录和原始寿命；保留已有在场数量上限。无限增值使用独立 `ReplicationGeneration` 并复用 `MaxSplitGeneration=2` 作复制代数上限，单颗原球最多扩展到 4 球；普通分流器仍使用自己的 `Generation`，两者不互相占用代数。
批量发射在扣血前检查全部球，任何一颗创建失败整批回滚。每颗都消耗自己的血耗，不把“多球”解释为免费生成。

## 验证

菜单 `Marbles ECS/Validate Attribute and Content Runtime` 在 Play 模式运行真实游戏系统和独立 PhysX 场景。
批处理入口 `MarblesECS.Editor.GameContentValidation.Run` 创建临时空场景，不保存游戏场景。
覆盖属性运算顺序、上下限、概率档位、批量回滚、10 种药物与快照、装置效果、传送配对、分裂守恒、复制继承、返血、经济，以及实际重力、限速、穿钉和磁力。

## 当前 RUSH 规则

全盘条值上限 100。普通球贡献 2，每次有效触发装置 +5，底部流失原值入账、得分区 ×1.5 入账。满条进入 10 秒 RUSH：免扣血、射速 +5 发/秒、所有球临时价值 +5；期间暂停条值入账，到期从 0 重新开始。降降火触发球额外 5 秒。装置增益 ×2 暂不实现，数值不变。台球和有锅气的 Lua 规则及迁移 API 见 [装置 Lua API](Device_Lua_API.md)。
