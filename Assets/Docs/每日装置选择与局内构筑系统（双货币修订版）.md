# 血色弹珠机：每日装置选择与局内构筑系统改造需求（Codex）

> **任务性质：** 在现有 Unity ECS
> 弹珠游戏基础上，增量开发每日装置选择、局内背包、装置购买安装及耐久损坏机制。
>
> **核心体验：**
> 玩家每天选择有限种类的装置带入生产阶段，在局内使用血肉残料购买并安装装置。装置经过一定次数的有效触发后会损坏，玩家需要持续补充装置，并根据当前生产需求动态调整布局。
>
> **双货币规则：**
> 每日通关后，公司发放局外货币「公司工票」，用于商店抽取装置种类的使用权限；局内通过经济钉子回收「血肉残料」，用于购买和安装具体装置实例。两种货币用途、存储范围和结算时机完全独立。

------------------------------------------------------------------------

## 1. 改造目标

将现有弹珠机玩法改造为类似《植物大战僵尸》的装置选择与局内构筑模式。

核心规则：

1.  每天开始时，根据当天解锁的装置种类，选择限定数量的装置类型放入背包。
2.  进入生产阶段后，玩家只能使用背包中已选择的装置。
3.  玩家通过局内货币「血肉残料」购买并安装装置实例。
4.  每个装置实例都有独立耐久度，每次有效触发生效时消耗一定耐久。
5.  耐久归零后，装置损坏并从盘面移除，释放原有位置。
6.  玩家可以使用血肉残料重新购买相同类型的装置，也可以更换其他装置，动态调整生产布局。
7.  随着日期推进，逐渐开放新的装置类型候选池。每日通关后公司发放公司工票，玩家在局外商店消耗工票，随机抽取装置种类的使用权限。

核心体验：

玩家每天拥有有限的装置种类选择，需要根据当天的生产目标和特殊规则决定携带哪些装置。进入生产后，先通过经济钉子回收血肉残料，再使用血肉残料购买生产装置。随着装置不断损坏，玩家需要持续调整布局，在资源回收和生产效率之间进行取舍。每日通关获得的公司工票则用于局外商店，获取更多装置种类的使用权限。

## 1.1 双货币体系

必须将局外货币与局内货币作为两套独立资源管理，不能继续用含义模糊的「金币」同时指代两者。

  --------------------------------------------------------------------------------------------------------------------------------
  货币 ID          显示名称   获取方式                             用途                               存储范围
  ---------------- ---------- ------------------------------------ ---------------------------------- ----------------------------
  `CompanyScrip`   公司工票   每日成功通关后，由公司作为奖励发放   在局外商店抽取装置种类的使用权限   Campaign 长期保存，跨 Day
                                                                                                      累积

  `BiomassScrap`   血肉残料   局内经济钉子从血珠中回收             购买、安装具体的装置实例           仅当前 Day /
                                                                                                      当前生产局有效，日结后清空
  --------------------------------------------------------------------------------------------------------------------------------

### 公司工票（局外货币）

-   每日成功通关并完成结算后，根据当天配置发放公司工票。
-   公司工票存入 Campaign 长期账户，跨 Day 保留。
-   公司工票只用于局外商店抽取装置种类的使用权限。
-   抽取成功后，玩家获得对应装置类型的使用权限；获得的是类型权限，不是一个已经安装的装置实例。
-   公司工票不能用于局内安装装置。
-   当天失败或未完成通关时，不发放当天的通关工票奖励。
-   通关奖励必须具备幂等性，避免结算事件重复触发时重复发放。

### 血肉残料（局内货币）

-   血肉残料是机器从血珠中回收、处理后留下的可再利用生物材料。
-   经济钉子每次有效触发时，将血珠当前价值减半，并回收 1 份血肉残料。
-   血肉残料用于局内购买和安装装置实例。
-   血肉残料不能用于局外商店抽取装置种类使用权限。
-   血肉残料在当天生产结束后清空，不带入下一 Day。
-   当天失败重试时，按照当天开始时的状态恢复，不允许通过重试复制或保留额外血肉残料。

### 实现约束

-   代码中使用明确的货币 ID，例如 `CompanyScrip` 和
    `BiomassScrap`，禁止继续使用含义不明确的 `Gold`、`Coin` 或单一
    `Currency` 字段同时表示两种货币。
-   如果项目已有通用货币系统，应扩展为可区分货币类型和存储范围的系统，不要另建互不兼容的账户体系。
-   局外商店交易必须显式指定 `CompanyScrip`。
-   局内装置安装交易必须显式指定 `BiomassScrap`。
-   UI 必须分别显示两种货币及其用途，不能只显示一个通用「金币」数值。
-   两种货币不能互相兑换，除非未来由独立策划配置明确提出。

## 3. 装置类型

目前添加规划五种装置类型。

  装置 ID            装置名称       效果
  ------------------ -------------- -----------------------------------------------
  `CoinPeg`          经济钉子       弹珠碰撞后，当前价值减半，并回收 1 份血肉残料
  `AddValuePeg`      +3 价值钉子    弹珠当前价值 +3
  `MultiplyPeg`      倍率钉子       弹珠当前价值 ×2
  `SplitPeg`         双生分裂钉子   额外生成一颗与原弹珠价值相同的弹珠
  `TripleSplitPeg`   三重分裂钉子   额外生成两颗与原弹珠价值相同的弹珠

具体效果优先复用项目中已有的装置实现。

每种装置应当具有以下数据：

-   唯一 ID
-   名称
-   装置类型
-   局内安装价格
-   最大耐久
-   弹性

装置价格、耐久和效果参数必须数据驱动，不要散落在多个 System 中。

优先沿用现有 GameContent
配置和装置定义。如有缺失再补充。

### 3.1 装置类型与装置实例的区别

必须区分：

**装置类型（Peg Definition）**

代表玩家解锁并放入背包的装置种类。

**装置实例（Peg Instance）**

代表玩家实际花费血肉残料安装在盘面上的一个装置，拥有独立耐久。

例如：

玩家背包中有 `CoinPeg`。

玩家可以花费血肉残料，在盘面安装多个 `CoinPeg`。

每个 `CoinPeg` 都有独立的耐久度，某个实例损坏后，不会导致背包中的
`CoinPeg` 类型消失。

只要背包中仍然拥有该类型，玩家就可以继续购买和安装新的实例。

## 4. 每日装置解锁与选择

每天开始时，根据当天的配置，向玩家提供可用装置类型。

玩家通过交互目前的shop机器打开页面。页面左边是背包，右边上方是可选择的装置，下方是商店抽取（在开启之前显示“暂时关闭”）

玩家只能将限定数量的装置类型放入背包。

这里限制的是装置种类数量，不是装置实例数量。

背包中的装置可以在局内重复购买，但每次安装都需要消耗血肉残料。

### Day 0：基础生产教学

可用装置：

-   `CoinPeg`：经济钉子
-   `AddValuePeg`：+3 价值钉子

当天只开放这两种装置。

背包种类上限：2。

两个装置均可选择。

本日教学重点：

1.  让玩家认识装置安装方式。
2.  学习经济钉子如何从血珠中回收血肉残料。
3.  学习血肉残料如何用于购买新的装置实例。
4.  学习 +3 价值钉子如何改变弹珠价值。
5.  体验装置耐久耗尽和重新补充。

不开放商店抽取功能。每个Day的配置里维护一个"DefaultPegs"，来表示不需要抽取，直接放在可选择的装置栏里的装置。

### Day 1：增加生产构筑类型

在 Day 0 的基础上解锁：

-   `MultiplyPeg`：倍率钉子
-   `SplitPeg`：双生分裂钉子
-   `TripleSplitPeg`：三重分裂钉子

此时总共解锁五种装置。

背包种类上限：4。

玩家需要从五种已解锁装置中选择最多四种放入背包。

本日教学重点：

1.  让玩家理解不同装置的组合效果。
2.  引入倍率与分裂机制。
3.  让玩家开始根据生产需求选择装置。
4.  让玩家理解装置种类选择本身也是一种策略。

Day 1 新增的三种装置进入当天的装置候选池。为保证教学体验，如果希望玩家在
Day 1 就能尝试全部五种装置，可以通过 `DefaultPegs`
为新增装置授予当日权限。

Day 1 不开放随机抽取，装置选择界面展示当天配置允许使用的装置。

### Day 2：引入商店抽取装置

从 Day 2 开始，引入商店抽取机制。

商店从当天配置指定的可抽取装置池中随机生成装置种类使用权限。每次抽取消耗公司工票，抽取结果不是装置实例，也不直接消耗或产生血肉残料。

建议初始配置：

-   每次商店展示 4 种不同装置类型供抽取，具体展示和抽取流程按现有商店交互适配。
-   同一轮展示中不出现重复装置类型。
-   玩家最多选择 3 种装置放入背包。
-   经济钉子作为基础装置，默认通过初始权限直接提供
-   其他商品从剩余已解锁装置中随机抽取。

商店的抽取、购买、刷新和货币扣除优先接入现有
`CampaignShopSystem`，但必须明确使用局外货币 `CompanyScrip`。

不要为本功能额外创建一套独立商店系统。整个功能只使用已定义的两种货币：局外公司工票
`CompanyScrip` 和局内血肉残料 `BiomassScrap`，不要再引入第三种货币。

如果现有商店机制无法支持装置类型抽取，先分析最小扩展方案。

商店展示的装置类型与实际局内安装的装置实例必须区分。

玩家在商店中每次抽取时花费公司工票，抽取结果授予对应装置类型的使用权限，而不是直接获得一个已经安装好的装置。抽取成功后，将权限写入对应的
Campaign / Day / Run
权限集合，再由每日背包界面选择装置类型。使用权限的持续范围由
`PegPermissionScope` 配置明确，不要将权限和装置实例混为一谈。

### 每日配置示意

  日期    解锁装置                       背包上限  商店
  ------- ----------------------------- ---------- --------------
  Day 0   经济、+3                          2      关闭
  Day 1   新增 ×2、双生分裂、三重分裂       3      关闭
  Day 2   解锁的全部装置                  3      开启随机抽取

上述背包上限和商店商品数量应当作为可修改配置，而不是写死在 System 中。

## 5. 背包系统

新增或扩展每日装置背包。

背包需要记录：

-   当前 Day ID。
-   当天已解锁的装置类型。
-   当天允许选择的装置种类上限。
-   当前已经选择的装置类型。
-   商店抽取获得的装置类型。
-   是否已经完成当天装置选择。

背包只负责管理当前生产阶段可以使用哪些装置类型。

不要将背包和盘面上的装置实例混为一谈。

必须区分以下四个概念：

1.  **装置候选池（Available Peg
    Pool）**：当前日期允许进入商店抽取或试用的装置类型。
2.  **装置使用权限（Peg
    Permission）**：玩家通过初始配置、免费试用或消耗公司工票抽取获得的类型使用权。
3.  **每日背包（Daily
    Loadout）**：玩家从当前拥有权限的装置类型中，选择限定数量带入当天生产的装置。
4.  **装置实例（Peg
    Instance）**：玩家在局内花费血肉残料实际安装到盘面上的对象，拥有独立耐久。

商店抽取只改变装置使用权限，不直接安装装置，也不直接占用每日背包格数。抽取获得权限后，玩家仍需在每日装置选择界面将对应类型放入背包。

权限有效范围由配置决定：

-   `CampaignPermanent`：永久加入 Campaign 已拥有权限列表。
-   `DayOnly`：仅在当前 Day 有效。
-   `RunOnly`：仅在当前生产局有效。

在策划未明确要求前，不要把这三种权限范围写死在核心系统中。

### 背包操作

1.  点击装置类型，将其加入背包。
2.  达到种类数量上限后，不允许继续添加。
3.  可以移除已经选择的装置类型。
4.  移除后可以重新选择其他类型。
5.  未解锁的装置不能加入背包。
6.  未放入背包的装置不能在局内购买和安装。

进入生产阶段后，背包内容作为当前 Day 的装置使用权限。

## 6. 局内装置购买与安装

玩家进入生产阶段后，装置购买面板只展示当前背包中已经选择的装置类型。

购买流程：

1.  玩家选择一种装置。
2.  显示装置名称、效果、价格和最大耐久。
3.  玩家选择盘面上的合法位置。
4.  检查血肉残料是否足够。
5.  血肉残料足够时扣除对应价格。
6.  创建新的装置实例并放置在指定位置。
7.  初始化该实例的最大耐久和当前耐久。

必须保证：

-   血肉残料不足时不能购买。
-   不允许在非法位置安装。
-   不允许覆盖已有装置。
-   购买失败不扣除血肉残料。
-   每次安装创建独立装置实例。
-   同一种装置允许重复安装。
-   装置类型是否在背包中，是购买时的权限判断依据。

优先复用现有装置拖动、放置、合法位置检测和描边反馈逻辑。

## 7. 装置耐久与损坏

所有装置都具有独立耐久。

装置每次有效触发生效时，耐久减少。

当耐久归零：

1.  触发装置损坏事件。
2.  停止该装置的玩法效果。
3.  移除或禁用该装置的碰撞体。
4.  清理对应的表现对象和运行时引用。
5.  将该位置恢复为空闲状态。
6.  允许玩家重新购买装置并安装到该位置。

注意：

-   只在装置效果真正生效时扣除耐久。
-   不要因为弹珠经过附近但没有触发效果就扣除耐久。
-   保留原有装置碰撞和物理反弹行为。
-   装置损坏不能导致正在运行的弹珠出现无效引用或物理异常。
-   装置实例损坏后，不能影响背包中对应的装置类型。
-   装置损坏事件应通过 ECS 事件或现有事件机制通知相关系统。

装置耐久应当能够在 UI 中实时显示。

建议使用现有耐久条、描边、损坏特效等表现。

### 内层生产 FSM

继续复用现有：

``` text

  |
  v
Playing
  |
  v
Draining
  |
  v
RoundSettlement
```

具体以项目真实状态机为准。

不要重新实现一套生产状态机。

### 每日状态重置

进入新 Day 时：

-   读取当天装置解锁配置。
-   初始化当天装置背包。
-   初始化当天商店状态。
-   初始化当天生产所需资源，包括当天的血肉残料初始值。
-   清理上一个 Day 的临时装置实例和局内运行时数据。
-   保留已经获得的装置种类使用权限、公司工票余额和 Campaign 长期进度。

### 每日通关奖励

-   当天成功完成生产并进入 `DaySettlement` 后，根据
    `DayDefinition.ClearCompanyScripReward` 发放公司工票。
-   公司工票进入 Campaign 长期账户，不进入当天局内资源账户。
-   发放操作必须有 Day ID / 结算记录作为幂等依据，避免同一 Day
    重复结算时重复发奖。
-   当天失败不发放通关工票奖励。
-   血肉残料只在当天生产局内使用，日结后清空，不作为通关奖励保留。

### 失败重试

当天生产失败时：

-   只重试当前 Day。
-   恢复当天开始时的运行状态，包括血肉残料余额。
-   恢复当天装置选择状态。
-   恢复并保留当天已经完成的商店抽取结果，避免通过失败重试免费刷新商品或重复扣除公司工票。
-   清理上一次尝试的弹珠、装置实例和临时碰撞对象。
-   不推进 Day Index。

当天成功后才进入结算、休息和下一天。

## 9. UI 改造需求

### 9.1 每日装置选择界面

进入生产前显示装置选择界面。

需要展示：

-   当前 Day。
-   当前已经解锁的装置类型。
-   每种装置的图标和名称。
-   装置效果说明。
-   每种装置的局内安装价格（以血肉残料计价）。
-   装置耐久。
-   当前背包容量。
-   当前已经选择的装置种类数量。

例如：

``` text
DAY 1

选择今天携带的装置

已选择：2 / 3

[经济钉子]  [ +3价值钉子 ]
[倍率钉子]  [双生分裂钉子]
[三重分裂钉子]

              开始生产
```

未解锁装置应当隐藏或显示为锁定状态。

### 9.2 Day 2 商店界面

展示随机抽取的装置商品。

每个商品需要展示：

-   装置图标。
-   装置名称。
-   装置效果。
-   商店抽取价格（以公司工票计价）。
-   是否已购买。
-   是否已经加入背包。

玩家可以从商品中选择装置类型，但不能超过背包容量。

### 9.2.1 局外商店货币显示

-   商店顶部明确显示「公司工票」余额。
-   每次抽取按钮显示工票消耗数量，例如「抽取（消耗 2 张工票）」。
-   抽取结果显示获得了哪一种装置类型的使用权限。
-   商店界面不得显示或扣除「血肉残料」。

### 9.3 局内购买界面

只展示当前背包中的装置。

每个装置显示：

-   图标。
-   名称。
-   安装价格。
-   最大耐久。
-   当前血肉残料是否足够。

玩家安装装置后，血肉残料余额立即更新。每日通关结算后，公司工票余额按奖励配置更新。

局内生产界面只显示「血肉残料」余额，不显示公司工票作为可用安装资金。两种余额应使用不同图标、颜色和说明。

装置损坏后，及时刷新盘面和装置选择 UI。

保留现有的合法位置绿色描边、非法位置红色描边和悬停说明功能。

## 10. 数据驱动与扩展要求

每日装置解锁、背包数量限制和商店抽取必须通过配置管理。

不要在核心 System 中写：

``` csharp
if (currentDay == 0)
{
    // ...
}
else if (currentDay == 1)
{
    // ...
}
```

建议根据现有项目配置体系扩展 Day Definition。

每一天至少能够配置：

``` text
DayDefinition
├── DayId
├── UnlockedPegIds                 # 当天开放 / 可进入候选池的装置类型
├── DefaultlPegIds                # 当天免费试用的装置类型
├── MaxLoadoutTypeCount
├── LoadoutSelectionMode
├── ShopEnabled
├── ShopCurrencyType               # 固定使用 CompanyScrip
├── ShopDrawCost                   # 每次抽取消耗的公司工票
├── ShopOfferCount
├── ShopGuaranteedPegIds
├── ShopRandomPool
├── ShopSelectionLimit
├── ShopRandomSeed
├── PegPermissionScope             # CampaignPermanent / DayOnly / RunOnly
└── ClearCompanyScripReward        # 当天成功通关后发放的公司工票
```

货币账户建议在现有账户系统中明确区分：

``` text
CampaignWallet
└── CompanyScripBalance             # 局外长期公司工票余额

RunWallet
└── BiomassScrapBalance             # 当前 Day 的局内血肉残料余额
```

具体字段和结构根据现有配置系统调整。

未来需要能够方便地：

-   增加新的装置类型。
-   修改装置价格和耐久。
-   修改每天的解锁内容。
-   修改背包种类数量上限。
-   开启或关闭某天的商店。
-   修改商店商品数量。
-   修改商店随机商品池。
-   设置某些装置为当天必选。
-   修改商店随机权重。

新增配置必须复用项目现有的 JSON / GameContent
加载、校验和深拷贝机制，不要维护两套配置体系。

## 11. 测试与验收标准

### Day 0

-   [ ] 只能使用经济钉子和 +3 价值钉子。
-   [ ] 背包最多选择两种装置。
-   [ ] 不能选择尚未解锁的装置。
-   [ ] 进入生产后只能购买背包中的装置。
-   [ ] 可以重复安装同一种装置。
-   [ ] 装置触发时正常扣除耐久。
-   [ ] 装置损坏后可以在原位置重新安装。

### Day 1

-   [ ] 解锁倍率钉子。
-   [ ] 解锁双生分裂钉子。
-   [ ] 解锁三重分裂钉子。
-   [ ] 总共可以使用五种装置。
-   [ ] 背包最多选择三种装置。
-   [ ] 未选中的装置不能在局内购买。
-   [ ] 原有装置效果不受影响。

### Day 2

-   [ ] 商店可以从已解锁装置池中生成随机商品。
-   [ ] 同一轮商品不重复。
-   [ ] 商店商品数量和背包容量符合配置。
-   [ ] 可以选择商品并加入背包。
-   [ ] 未获得的装置类型不能在局内购买。
-   [ ] 刷新和重新进入商店不会产生异常重复购买。
-   [ ] 失败重试不会免费刷新当天商品，也不会重复扣除公司工票。

### 双货币与奖励

-   [ ] 每日成功通关后按配置发放公司工票。
-   [ ] 同一 Day 的通关奖励只能发放一次。
-   [ ] 失败时不发放公司工票通关奖励。
-   [ ] 公司工票跨 Day 保存。
-   [ ] 血肉残料只在当前 Day / 生产局内使用，日结后清空。
-   [ ] 商店抽取只消耗公司工票，不消耗血肉残料。
-   [ ] 局内安装只消耗血肉残料，不消耗公司工票。
-   [ ] UI 明确区分「公司工票」和「血肉残料」。

### ECS 与回归

-   [ ] 外层 Day FSM 不增加新的常驻状态。
-   [ ] 现有 Build / Playing / Draining / Shop 等流程正常。
-   [ ] 现有 PhysX 弹珠碰撞不受影响。
-   [ ]
    公司工票与血肉残料账户独立，商店只扣公司工票，局内安装只扣血肉残料。
-   [ ] 装置损坏后不会遗留碰撞体。
-   [ ] 失败重试不会遗留旧装置实例。
-   [ ] 新增配置能够通过校验。
-   [ ] 原有 TestScene 和已有测试流程仍可运行。
